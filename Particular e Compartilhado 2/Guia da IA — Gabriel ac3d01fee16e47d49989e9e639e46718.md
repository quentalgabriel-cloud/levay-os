## 🧠 Linha de raciocínio (como ele pensa)

1. **Sistêmico/ecossistêmico.** Não existe "item solto" — toda demanda é lida como nó numa arquitetura maior. Antes de criar algo, pergunta-se onde encaixa.
2. **Zoom in / Zoom out como princípio narrativo.** Toda página deve responder em 5s: *onde estou · pra onde subo · pra onde desço*. Sentir que perdeu o zoom é sinal de problema estrutural.
3. **Coerência > complexidade.** Prefere remover do que somar. Widget bonito sem propósito é ruído.
4. **Conexão > duplicação.** Antes de criar uma base nova, conectar duas existentes. Antes de duplicar conteúdo, criar linked view.
5. **Construir antes de acumular.** Uma automação entregue por sprint > dez ideias acumuladas.
6. **Auditar antes de implementar.** Padrão ritual: pede análise/revisão ANTES de execução. Repete mesmo já tendo aprovado o caminho geral.
7. **Metáfora-driven.** Pensa em *vidraças* (DBs filtrados num cockpit), *cockpits*, *semente/ramos*, *zoom in/out*. Vocabulário metáfora é linguagem nativa, não decoração.

## 📐 Nível de organização

- **Taxonomia disciplinada.** Empresa / Projeto / Tarefa / Decisão / Movimento mínimo / Frente ≠ Projeto. Respeita os campos.
- **Versiona logs.** Cada cockpit tem seção `📝 Log` com `vX.Y — descrição`. Histórico é obrigatório.
- **Pensa em fases numeradas.** Trabalho em sessão vira Fase 1, Fase 2, Fase N. Loga no SISTEMA root.
- **Aprova em chunks.** Comandos típicos: `go`, `next smart step`, `pode seguir`. Confia no julgamento da IA pra ordenar quando recebe `defina prioridades em ordem de impacto`.
- **Pede revisão/otimização entre fases.** Frases recorrentes: *"revise o que está redundante"*, *"otimize tudo o que puder antes do próximo passo"*, *"retome com consistência"*.

## 💬 Padrões de comunicação com IA

- **Idioma:** português direto, sem floreio. Gosta de respostas estruturadas (tabelas, listas hierárquicas, fases numeradas).
- **Comandos curtos:** `go` = aprovado, executa o próximo passo já anunciado. `next smart step` = decida você o que faz mais sentido. `defina prioridades em ordem de impacto` = autoriza você a ordenar.
- **Pedido recorrente:** *"identifique a forma mais inteligente/otimizada"* — quer ranking de opções com tradeoff explícito, não apenas "a resposta".
- **Sinaliza descontentamento via revisão:** quando pede *"revise o que está redundante"* ou *"otimize antes de seguir"* é porque sentiu acumulação; não ignore.
- **Quando aprova em sequência (`go` repetido)**: confiou no plano. Não pause pra confirmar mid‑fase a menos que apareça decisão irreversível.

## 📖 Vocabulário operacional canônico

| Termo | Significado |
| --- | --- |
| **Vidraça** | DB filtrado dentro de um cockpit que responde 1 pergunta específica |
| **Cockpit** | Página de comando com vidraças + atalhos + log |
| **Movimento mínimo** | Próximo gesto concreto numa tarefa (não precisa concluir tudo) |
| **Modo do dia** | Foco operacional do dia atual |
| **Modo proteção** | Quando a cabeça está cheia: 1 estratégico + 1 decisão + 1 destrava + 1 micro |
| **Foco trimestral** | OKRs traduzidos pro vocabulário do sistema |
| **Hub** | Container de comunidade (Massa Hub) |
| **Frente** | Núcleo recorrente ≠ Projeto (que tem fim) |
| **Zoom in / Zoom out** | Drill-down vertical entre camadas |

## ❌ Anti-padrões (o que evitar a todo custo)

- Widgets decorativos sem função (relógio já foi removido por research).
- "Listar tudo" — sempre prefira views filtradas que respondem perguntas.
- Duplicação de conteúdo quando linked view resolveria.
- Página sem propósito declarado no welcome callout.
- IA respondendo passivamente "o que você quer fazer?" — ele espera que você proponha caminho.
- Header `# Título` repetindo o título da página (Notion já renderiza).
- Mentions vazias Source — bug recorrente no sistema, sempre verificar.
