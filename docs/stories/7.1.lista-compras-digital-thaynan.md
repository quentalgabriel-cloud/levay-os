# Story 7.1 — Lista de Compras Digital (Sprint 1)

## Princípio decisório
"Tirar Erick do WhatsApp em UMA dor real, com substrato modular que sirva às outras dores que virão depois."

A Sprint 1 entrega a primeira frente onde Thaynan opera de verdade. Quintas (dia da loucura) deixam de ser caóticas. Erick só vê **exceções**.

## Atores e fluxo

| Ator | Ação | Quando |
|---|---|---|
| Suedney / Rafael | Lança itens da lista (mobile) | Terça (BICA), Quarta manhã (AMP) |
| Lana | Lança itens da casa (mobile) | Sempre que falta |
| Thaynan | Consolida pedidos, dispara fornecedor via WhatsApp do app | Quarta tarde |
| Fornecedor | Confirma valores + prazo | Quarta-Quinta |
| Suedney / Rafael / Lana | Marca recebido na unidade | Quinta-Sexta |
| Erick | Aprova **exceções** (acima_teto, fornecedor_novo, ruptura) | Sob demanda |

## Acceptance Criteria

### AC1 — Suedney lança lista em <5 min (mobile)
- [ ] Tela `/compras/nova` responsiva, otimizada para celular
- [ ] Form mínimo: company (BICA | AMP | PESSOAL), needed_by, lista de itens (add/remove inline)
- [ ] Cada item: description, quantity, unit (select), estimated_unit_price (opcional)
- [ ] Submit cria 1 `procurement_request` + N `procurement_items` em 1 Server Action transacional
- [ ] `idempotency_key` gerado client-side (`useRef(crypto.randomUUID())`) — re-submit não duplica
- [ ] Toast de confirmação + redirect para `/compras`

### AC2 — Thaynan vê todos pedidos da semana
- [ ] Tela `/compras` lista pedidos por status (kanban-like): solicitado | consolidado | comprado | recebido
- [ ] Filtros: company (BICA/AMP/PESSOAL), needed_by (essa semana / próximos 7 dias / atrasados), exception
- [ ] Cada card mostra: title, company, needed_by, # de itens, estimated_total, exception_flagged
- [ ] Click no card abre detalhe `/compras/[id]`

### AC3 — Thaynan consolida pedido e dispara fornecedor
- [ ] Detalhe permite editar items (quantidade, preço estimado)
- [ ] Botão "Consolidar" muda status `solicitado → consolidado`, registra `consolidated_at`, `consolidated_by`
- [ ] Botão "Enviar p/ fornecedor" abre modal com:
  - [ ] Select de supplier (com busca, criação inline se novo)
  - [ ] Texto pré-formatado com lista de itens (copy-paste pra WhatsApp)
  - [ ] Link `wa.me/{supplier.whatsapp}?text={mensagem}` (abre WhatsApp Web/app)
- [ ] Após enviar, status muda `consolidado → comprado` ao registrar valores reais

### AC4 — Recebimento na unidade
- [ ] Detalhe permite marcar item como `recebido` (mobile-friendly checkbox)
- [ ] Campo `quantity_received` opcional (default = quantity_requested)
- [ ] Campo `actual_unit_price` permite ajuste se valor real divergiu
- [ ] Quando todos items `recebido`, request muda para `recebido` automaticamente
- [ ] Trigger registra evento em `procurement_history`

### AC5 — Exceções escalam para Erick
- [ ] Sistema flaga `exception_flagged=TRUE` automaticamente quando:
  - estimated_total > teto do company (definido em `workspace_config.key='procurement_caps'` JSONB)
  - supplier_id é NULL e supplier criado nas últimas 24h (fornecedor novo)
  - Item marcado como `rupture` manualmente
- [ ] Tela `/mesa` (do Erick) mostra widget "Exceções de Compras" com lista
- [ ] Erick clica → vê detalhe → aprova ou rejeita
- [ ] Aprovação registra `approved_by` + `approved_at` + evento `exception_resolved`

### AC6 — Audit trail completo
- [ ] Toda mudança de status grava evento em `procurement_history` via `log_procurement_event()` (helper SQL provido na migration)
- [ ] Timeline visível em `/compras/[id]` com eventos cronológicos
- [ ] Eventos mínimos: `created`, `consolidated`, `sent_to_supplier`, `supplier_confirmed`, `received`, `exception_flagged`, `exception_resolved`, `cancelled`, `rupture_detected`

### AC7 — Dashboard Thaynan
- [ ] Widget na `/mesa` ou rota dedicada `/compras/dashboard` exibe (lê de `procurement_dashboard_v`):
  - Por company: qtd_solicitados, qtd_consolidados, qtd_comprados, qtd_excecoes, valor_estimado_aberto, próxima_data_necessaria
- [ ] Refresh automático ao mutar (revalidatePath após Server Action)

### AC8 — Performance + Quality gates
- [ ] `npm run lint && npm test && npm run typecheck` passa
- [ ] LCP < 2.5s na `/compras` e `/compras/nova` (medido via Lighthouse mobile)
- [ ] RLS testada: usuário de workspace A não vê dados de workspace B
- [ ] Server Action de criação testa cenário de retry (mesmo `idempotency_key` 2× → retorna o mesmo request sem duplicar)
